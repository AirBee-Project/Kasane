# 変数名のルール
- トランザクションは`read_txn`か`write_txn`とする。同じスコープに複数のトランザクションが並ぶことはないはずなので、この使い分けで大丈夫。
- Kasane（このソフトウェア自体）にも`Table`の概念が存在しており、redbの`Table`と衝突しやすい。そこでredbのtableは`redb_{Table定義の定数の小文字}`という名前をつける。同じスコープで同じTableを開くことはないと思うのでこの使い分けで大丈夫。
- redbにはReadとWriteのトランザクションを横断する概念が存在しない。そのため、SpatialDbにもRead型とWrite型を作って、それぞれの動作を定義する。ボイラーコードになるかもしれないが、抽象化にかかるコストは未知数だし、構造が複雑化するよりはまし。可能な限り同じ挙動になるようにする。後でSpatialDB Traitを作って抽象化するかもしれない。
